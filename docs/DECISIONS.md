# DECISIONS

## 2026-03-17

### 为什么当前先做 U1.2
- 决策：当前先做 `U1.2 前台文案口语化真收口`，不切新功能轮。
- 原因：`U1` 和 `U1.1` 已把结构和视觉收住，但真实页面验收时，家长页、孩子页、会员页仍残留后台味、技术字段味和术语味，家长读起来还不够像陈老师在说话。

### U1.2 只收前台文案，不动逻辑底座
- 决策：本轮只改家长总览页、孩子首页、会员页、相关 CTA 与它们依赖的前台文案来源，不新增业务逻辑，不改后端契约，不碰多学生隔离底座。
- 原因：这轮要解决的是“说得不够人话”，不是“能力不够”。

### U1.2 的文案原则
- 决策：本轮前台文案统一遵守以下原则：
  1. 先结论，后解释
  2. 用短句，不写报告腔
  3. 用家长听得懂的话，不用系统术语
  4. 家长页强调“现在卡哪、为什么还要继续跟”
  5. 孩子页强调“今天先做什么、下次回来看什么”
  6. 会员页强调“差异、边界、升级理由”
- 原因：目标是把前台页面从“已经像产品”推进到“真能拿给家长看”。

### U1.2 的技术收口要求
- 决策：前台目标页不再出现以下表述：`证据时间轴`、`定向素材`、`老师纠偏`、`学生自述`、`timeline-*`、内部字段名。
- 原因：这些词一旦露出来，页面立刻会重新变回后台页。

### U1.2 已完成
- 决策：`U1.2` 在本轮完成后正式收口。
- 原因：家长页、孩子页、会员页的目标文案已统一收成口语化表达；桌面与移动视口重新验页；`npm run typecheck`、`npm run build`、`npm exec playwright test` 已全部通过；截图已导出。

### 真机访问的运行说明
- 决策：真机访问不通过代码改造实现，而通过启动方式控制。
- 原因：当前仓库无需新增逻辑；如要同局域网手机访问，应以 `--hostname 0.0.0.0` 启动，并使用本机局域网地址访问，例如 `http://192.168.0.102:3000/login`。

### U1.2 之后的下一轮候选
- 决策：`U1.2` 之后优先进入：
  1. 数据接口清单
  2. 自动录入待审核队列
  3. 人工审核确认流
- 原因：前台表达已经基本收干净，下一步更值得补的是审核准备链路。
