# Capability Registry

- Every major capability should have a clear owner layer:
  - data source
  - API boundary
  - page entry
  - e2e coverage
- Current high-priority capabilities:
  - diagnosis main chain
  - recheck loop
  - evidence timeline
  - continue-tracking conversion
  - membership state management
  - multi-student isolation
- New work should extend an existing capability whenever possible before adding a new subsystem.
- If a capability is only present in UI copy and not in backend enforcement, it is incomplete.
